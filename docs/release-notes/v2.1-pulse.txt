🔔  REAL WEB PUSH NOTIFICATIONS  (iOS PWA, Mac, Android, Windows)

   This is the marquee feature. The app now sends OS-level
   push notifications that arrive even when the app is closed —
   the same way WhatsApp or Instagram notify you.

   • Works on iOS 16.4+ when installed as a PWA (Add to Home Screen)
   • Works on macOS Safari, Chrome, Firefox, Edge
   • Multiple devices per user — each registered separately
   • Per-device enable/disable toggle
   • Cost: $0 forever (uses Apple/Google free push services)

───────────────────────────────────────────────────────────────────
  🏗  ARCHITECTURE — WHAT WE BUILT
───────────────────────────────────────────────────────────────────

CLIENT SIDE  (m-way app.html + sw.js + manifest.json)

   • Service Worker (sw.js): registers in browser, listens for
     OS push events, displays the notification.
   • PWA manifest (manifest.json): declares the app to iOS so
     Safari treats it as a real installable app with full push
     support.
   • VAPID public key embedded in app — used to subscribe.
   • Robust subscribe() flow with stage tracking + 10-second
     timeouts and detailed error reporting at each stage:
       1. Permission
       2. Service Worker registration
       3. Service Worker activation
       4. Push subscription
       5. Save to Supabase

SERVER SIDE  (Supabase Edge Function: handle-event)

   • Deno runtime — TypeScript file deployed to Supabase.
   • Uses web-push@3.6.7 (npm package) for native Web Push.
   • Receives Database Webhook payloads from Supabase, decides
     what to notify, looks up subscriptions, sends pushes in
     parallel using VAPID-signed Web Push protocol.
   • Auto-disables dead endpoints (HTTP 410/404 from push
     service) so we don't keep trying broken subscriptions.
   • Updates last_used_at on every successful push for analytics.
   • Custody-threshold detection (50/80/100%) computed by
     summing all member expenses and comparing to custody.

DATABASE WEBHOOKS  (5 webhooks, all → handle-event)

   • expenses                 (INSERT, UPDATE)
   • custody_requests         (INSERT, UPDATE)
   • team_members             (INSERT, UPDATE)
   • custody_transfers        (INSERT)
   • app_message              (INSERT)

   All 5 created via a single SQL script (much faster than
   the click-through UI).


───────────────────────────────────────────────────────────────────
  📦  MIGRATIONS REQUIRED
───────────────────────────────────────────────────────────────────

   1. Create the push_subscriptions table:

      CREATE TABLE IF NOT EXISTS push_subscriptions (
        id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
        user_id       text NOT NULL,
        user_role     text NOT NULL,
        device_label  text,
        endpoint      text NOT NULL,
        p256dh_key    text NOT NULL,
        auth_key      text NOT NULL,
        enabled       boolean DEFAULT true,
        created_at    timestamptz DEFAULT now(),
        last_used_at  timestamptz DEFAULT now(),
        UNIQUE(endpoint)
      );
      CREATE INDEX IF NOT EXISTS idx_push_subscriptions_user
        ON push_subscriptions(user_id, enabled);
      ALTER TABLE push_subscriptions ENABLE ROW LEVEL SECURITY;
      CREATE POLICY "push_subscriptions_all" ON push_subscriptions
        FOR ALL USING (true) WITH CHECK (true);

   2. Add VAPID secrets to Supabase Edge Functions:
        VAPID_PUBLIC_KEY    = (the base64 public key)
        VAPID_PRIVATE_KEY   = (kept secret, used by Edge Function only)
        VAPID_SUBJECT       = mailto:faresomaralhazmi@gmail.com

   3. Deploy the handle-event Edge Function
      (TypeScript source preserved in /edge-functions/ for reference)

   4. Configure 5 Database Webhooks (SQL script in release notes)
      All pointing to handle-event.

   All steps are documented in the release archive.
